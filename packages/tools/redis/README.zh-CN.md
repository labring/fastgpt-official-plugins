# Redis 缓存操作工具集 (Redis Cache)

Redis 缓存操作工具集是 FastGPT 官方提供的轻量级、高性能分布式缓存插件。通过与远程或本地 Redis 数据库交互，为智能体与工作流提供高速键值读写、生存时间（TTL）生命周期控制及键删除管理能力。

本工具集统一管理 Redis 连接配置，下挂 `get`、`set`、`del` 三个原子操作子工具，帮助工作流实现跨会话数据暂存、状态共享与限流控制。

---

## 典型应用场景

- **跨会话对话状态与上下文持久化暂存**：跨用户会话或在长程复杂交互中存储用户状态偏好、会话中间产物或草稿，避免反复调用大模型重构状态。
- **用户请求限频与分布式锁**：结合 TTL 记录特定用户/IP 的访问时间戳或调用计数，防止智能体接口被恶意高频刷取；配合临时键实现简易互斥锁。
- **临时动态验证码或 Token 存取**：存储短信/邮箱验证码、第三方 OAuth access_token，设置精确的秒级过期时间，实现自动失效与校验。
- **多节点临时中间结果共享**：在复杂工作流编排中，多分支并行或跨节点传递大文本、结构化中间计算结果，无需将庞大数据塞入上下文提示词中。

## 连接配置与密钥说明

使用本工具集前，需要在 FastGPT 密钥管理或工具集配置中填入 Redis 连接串（`redisUrl`）。所有子工具（`get`、`set`、`del`）均共享该配置。

### 密钥配置项

| 字段名 | 字段类型 | 必填 | 密钥脱敏 | 说明 |
| --- | --- | --- | --- | --- |
| `redisUrl` | 字符串 (`string`) | 是 | 是 (`isSecret`) | Redis 数据库的统一连接 URL，支持标准协议与带凭据连接串。 |

### `redisUrl` 格式规范与解析

连接串需符合标准 URI 格式，常见写法如下：

| 连接类型 | URL 格式示例 | 说明 |
| --- | --- | --- |
| **标准单机（无密码）** | `redis://127.0.0.1:6379/0` | 默认端口为 `6379`，`/0` 代表操作 0 号逻辑数据库。 |
| **经典密码认证（无用户名）** | `redis://:your_password@127.0.0.1:6379/0` | 注意若没有用户名，密码前必须保留冒号 `:`。 |
| **Redis 6+ ACL 认证（带用户名与密码）** | `redis://default:your_password@127.0.0.1:6379/0` | 适用于配置了多用户的 Redis 6 及以上版本。 |
| **TLS/SSL 加密连接** | `rediss://:your_password@your-redis-host.com:6379/0` | 协议头使用 `rediss://`（双写 `s`），适用于云托管加密通道。 |
| **云托管服务（如 Upstash）** | `rediss://default:your_password@xxx.upstash.io:6379` | 支持 Upstash、AWS ElastiCache、阿里云、腾讯云等托管实例。 |

> **安全提示**：
> `redisUrl` 被声明为 `isSecret: true`。在 FastGPT 平台中会被安全加密持久化，在前端界面展示、运行日志打印及调试数据流中均会自动进行脱敏保护，防止数据库认证密码泄露。

## 子工具列表

本工具集包含以下 3 个核心子工具：

- **`get`（获取缓存 / Get Cache）**：根据键名读取 Redis 中存储的值，并返回该键是否存在。
- **`set`（设置缓存 / Set Cache）**：写入或更新指定的缓存键值，支持指定秒级生存时间（TTL）。
- **`del`（删除缓存 / Delete Cache）**：删除指定的缓存键及其关联的数据。

---

## 子工具详情与参数说明

### 1. 获取缓存 (Get Cache / `get`)

根据指定的键名从 Redis 中检索对应的数据。如果键存在，返回具体字符串值；如果键不存在或已过期失效，返回 `null`。

#### 输入参数

| 参数名 | 字段类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `key` | 字符串 (`string`) | 是 | 无 | **要读取的 Redis 缓存键名**。不能为空字符串，例如 `fastgpt:session:user_123`。 |

#### 输出结果

| 字段名 | 字段类型 | 说明 |
| --- | --- | --- |
| `value` | 可空字符串 (`string \| null`) | **缓存数据**。如果键存在则返回对应的字符串内容；如果键不存在或已过期，则返回 `null`。 |
| `exists` | 布尔值 (`boolean`) | **键是否存在**。当该键在 Redis 中存在时返回 `true`，不存在或已过期时返回 `false`。 |

#### 输出示例

- **键存在时的返回值：**

```json
{
  "value": "{\"step\": 2, \"draft\": \"会议纪要初稿\"}",
  "exists": true
}
```

- **键不存在（或已过期）时的返回值：**

```json
{
  "value": null,
  "exists": false
}
```

---

### 2. 设置缓存 (Set Cache / `set`)

向 Redis 写入指定的键值对。支持配置可选的 `ttl` 参数以实现缓存自动失效。

#### 输入参数

| 参数名 | 字段类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `key` | 字符串 (`string`) | 是 | 无 | **要设置的 Redis 缓存键名**。不能为空字符串。 |
| `value` | 字符串 (`string`) | 是 | 无 | **要存入 Redis 的字符串数据**。若需存储对象或数组，请先转换为 JSON 字符串。 |
| `ttl` | 整数 (`number`) | 否 | `0` | **数据过期时间（秒）**。非负整数；设为 `0` 或缺省时表示该键永不过期。 |

#### 输出结果

| 字段名 | 字段类型 | 说明 |
| --- | --- | --- |
| `success` | 布尔值 (`boolean`) | **操作是否成功**。写入成功时返回 `true`。 |

#### 输出示例

```json
{
  "success": true
}
```

---

### 3. 删除缓存 (Delete Cache / `del`)

从 Redis 中主动删除指定的键。如果该键原本就存在并被成功删除，返回 `deleted: true`；若该键本身不存在，则返回 `deleted: false`。

#### 输入参数

| 参数名 | 字段类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `key` | 字符串 (`string`) | 是 | 无 | **要删除的 Redis 缓存键名**。不能为空字符串。 |

#### 输出结果

| 字段名 | 字段类型 | 说明 |
| --- | --- | --- |
| `deleted` | 布尔值 (`boolean`) | **是否已删除**。如果键原本存在且被成功删除返回 `true`；若键不存在则返回 `false`。 |

#### 输出示例

- **成功删除存在的键：**

```json
{
  "deleted": true
}
```

- **删除不存在的键：**

```json
{
  "deleted": false
}
```

## 典型工作流编排示例

### 场景一：跨轮次对话上下文与用户会话状态暂存

在需要长程交互的智能体工作流（如多步表单收集、分步骤方案生成）中，结合 TTL 实现会话状态的安全暂存与自动失效：

1. **读取上一次状态**：工作流启动时，调用 `get` 工具，设置 `key = fastgpt:session:{{chatId}}`。
2. **条件分支判断**：
   - 若 `exists == true`：将读取到的 `value` 注入到大模型的上下文提示词中作为历史会话状态。
   - 若 `exists == false`：引导大模型走初始欢迎与第一步提问逻辑。
3. **状态更新并写回**：在大模型完成本轮对话步骤后，调用 `set` 工具更新 `key = fastgpt:session:{{chatId}}`，并将 `ttl` 设为 `86400`（24 小时）。用户若在 24 小时内继续对话可无缝衔接，超时后 Redis 自动回收，不占多余内存。

### 场景二：用户请求频次限制与临时验证码存取

在面向外部用户的智能体中防止滥用或用于验证场景：

1. **下发验证码**：用户申请验证码时，生成 6 位随机码，调用 `set` 工具设置 `key = fastgpt:verify:{{phone}}`，`value = {{code}}`，`ttl = 300`（有效期 5 分钟）。
2. **核验并即时销毁**：用户提交验证码后，工作流调用 `get` 读取比对。若校验一致，立即调用 `del` 工具删除该 `key`，防止验证码被二次利用；若校验失败或已过期（`exists == false`），则提示重新获取。

### 场景三：工作流多节点临时中间计算结果解耦共享

在包含多分支并行的复杂编排中，避免在工作流连线之间传递巨大体积的文本：

1. **大文本存入**：上游文档检索或清洗节点将数万字的中间分析结果调用 `set` 工具存入 `fastgpt:temp:analysis:{{workflowInstanceId}}`，设置短 TTL（如 `1800` 秒）。
2. **下游按需调取**：下游多个并行的图表生成、要点提炼节点分别通过 `get` 按需读取，完成后由收尾节点调用 `del` 主动清理，提升工作流传输效率与稳定性。

## 注意事项与最佳实践

1. **环境与实例兼容性**：
   - 兼容标准 Redis 5.0+、Redis 6.x / 7.x（含 ACL 用户权限控制）。
   - 全面兼容主流云托管 Redis 服务（如阿里云 ApsaraDB for Redis、腾讯云 CRS、AWS ElastiCache、Upstash 等）。
2. **网络连通性与白名单配置**：
   - 请确保 FastGPT 服务所在的宿主机或容器能够通过 TCP 访问到 Redis 的 IP/域名及对应端口。
   - 若使用公网 Redis，务必在云服务器安全组与 Redis 防火墙白名单中放行 FastGPT 宿主机的出口 IP，并建议开启 SSL/TLS 加密传输。
3. **键名命名空间规范 (Namespace)**：
   - 强烈推荐使用冒号分层命名规范：`fastgpt:<模块/功能>:<业务标识>`。
   - 推荐示例：
     - 用户会话状态：`fastgpt:session:<chat_id>`
     - 频率限制计数：`fastgpt:ratelimit:<user_id>:<timestamp>`
     - 临时鉴权凭据：`fastgpt:auth:token:<token_id>`
   - 规范的命名有助于避免多个智能体共用 Redis 时的键冲突，且方便在 Redis GUI 中做分组查看与排查。
4. **数据类型与序列化约定**：
   - 本工具集的底层基于 Redis 的标准 String 类型操作。
   - 若需要存储 JSON 格式的结构化数据（如对象、数组），请在写入前序列化为标准 JSON 字符串；在下游节点通过 FastGPT 内置的代码节点或 JSON 提取器进行反序列化解析。
5. **连接生命周期与错误处理机制**：
   - 工具内置了健全的连接配置（10 秒连接超时、5 秒命令执行超时及指数退避重试机制）。
   - 每次子工具执行完毕后均会在 `finally` 中主动释放连接客户端（`client.quit()`），防止连接泄漏耗尽 Redis 连接池。
   - 针对连接拒绝（`ECONNREFUSED`）、超时（`ETIMEDOUT`）、密码鉴权失败（`NOAUTH`）等常见场景，插件会提供语义清晰的错误提示信息。
