# 多平台热榜工具 (Daily Hot)

多平台热榜工具（Daily Hot）用于实时聚合抓取主流互联网内容平台的热门榜单与实时热搜资讯。支持 **36氪**、**知乎**、**微博**、**掘金** 和 **今日头条** 等多个主流平台，帮助 FastGPT 智能体快速获取多维度的网络舆情动态、前沿科技热点与行业资讯。

本插件**开箱即用，无需配置任何第三方 API 密钥**。底层采用并行请求与容错降级机制，单个数据源异常不影响其他平台的正常返回，为自动化工作流与智能体应用提供稳定、实时的资讯输入。

---

## 应用场景

- **每日早报与资讯晨报自动生成**：结合 FastGPT 定时触发器，每日固定时间拉取科技创投（36氪）、技术生态（掘金）与全网大众热点（微博/头条），由大语言模型（LLM）筛选去重、提炼要点并排版，一键推送到企业微信或钉钉群。
- **行业与前沿技术热点追踪**：专注于科技商业要闻与开发者社区动态，智能识别大模型发布、开源项目突破、投融资事件等高价值信息，辅助产研团队或分析师把握前沿动态。
- **全网社交舆情与热点事件监控**：聚合微博实时热搜、知乎深度热榜与今日头条，监控突发公共事件、社会舆论动向与热点话题走势，进行情感倾向分析或风险预警。
- **自媒体创作与选题灵感库**：为自媒体创作者、运营人员提供跨平台实时热点池，智能体结合不同平台受众偏好推荐讨论切入点、文章选题与创作大纲。

| 平台标识 (`sources`) | 平台名称 | 领域分类 | 提供字段 | 平台内容特色与说明 |
| --- | --- | --- | --- | --- |
| `36kr` | 36氪 | 科技商业 / 创投资讯 | `title`, `source`, `time` | 聚焦科技、商业、创业投资领域的高热度事件与深度资讯，提供准确的资讯发布时间。 |
| `zhihu` | 知乎 | 深度问答 / 综合讨论 | `title`, `description`, `source`, `time` | 汇聚知乎全网讨论热度最高的热榜问题，包含问题摘要导读（`description`）与创建时间。 |
| `weibo` | 微博 | 社交媒体 / 实时热搜 | `title`, `source` | 微博实时热搜榜，体现全网网民关注焦点，时效性强、突发事件反应迅速。 |
| `juejin` | 掘金 | 开发者 / 技术社区 | `title`, `source` | 掘金技术社区综合文章热榜，覆盖前端、后端、AI、架构等开发者关注的热门技术文章。 |
| `toutiao` | 今日头条 | 综合资讯 / 民生热点 | `title`, `source` | 头条全网热搜热榜，涵盖社会民生、时事要闻、文娱生活等多维度综合热点。 |

## 输入参数

| 参数名 | 类型 | 默认值 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `sources` | 数组 (`Array<string>`) | `["36kr"]` | 否 | **热榜来源平台列表**。可选择一个或多个平台。可选枚举值：<br>• `"36kr"`：36氪热榜<br>• `"zhihu"`：知乎热榜<br>• `"weibo"`：微博实时热搜<br>• `"juejin"`：掘金技术文章热榜<br>• `"toutiao"`：今日头条热榜 |

> **提示**：在 FastGPT 编排中未传入 `sources` 或传入空时，插件默认抓取 `["36kr"]`。如需获取多个平台，可在工作流中传入数组，例如 `["36kr", "zhihu", "weibo"]`。

## 输出结果

插件调用完成后返回顶层对象，包含 `hotNewsList` 列表：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `hotNewsList` | 数组 (`Array<Object>`) | 各指定平台聚合返回的热榜新闻列表。 |

### `hotNewsList` 条目数据结构

`hotNewsList` 列表内包含两种类型的条目（联合类型 `Union`）：**成功获取的条目**与**平台获取失败的异常条目**。

#### 1. 成功数据条目 (Success Item)

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | 字符串 (`string`) | 否 | 热榜新闻、文章或热搜条目的标题。 |
| `description` | 字符串 (`string`) | 否 | 热榜条目的补充描述或内容摘要（目前主要由**知乎**平台返回）。 |
| `source` | 字符串 (`string`) | 是 | 数据来源平台的中文名称，如 `'36氪'`、`'知乎'`、`'微博'`、`'掘金'`、`'头条'`。 |
| `time` | 字符串 (`string`) | 否 | 新闻或条目的发布/创建时间（本地化格式化字符串，如 `2025/2/20 09:30:00`，由 **36氪** 与 **知乎** 提供）。 |

#### 2. 异常数据条目 (Error Item)

当某个平台因网络波动、上游接口异常导致请求失败时，容错机制会记录该平台的错误条目，而不阻断其他正常平台的返回：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `source` | 字符串 (`string`) | 是 | 发生请求异常的平台英文标识符（如 `'36kr'`、`'weibo'` 等）。 |
| `error` | 字符串 (`string`) | 否 | 错误信息描述，格式形如 `Failed to get hot news from <source>`。 |

> **说明**：只有在所选的所有平台全部请求失败且没有任何数据返回时，插件才会抛出顶层异常 `Failed to get hot news list`。

## 典型工作流编排与调用示例

### 工作流编排架构

```
[定时触发器 / 用户提问]
       │
       ▼
[热榜工具节点 (dailyHot)] ──> 输入 sources: ["36kr", "juejin", "zhihu"]
       │
       ▼
[大模型 (LLM) 节点] ────────> 注入 Prompt 进行筛选、去重、分类总结
       │
       ▼
[消息推送 / 回复节点] ─────> 输出精简日报至聊天界面、企业微信或钉钉群
```

---

### 示例一：每日科技与商业晨报生成

#### 1. 工具节点输入配置

```json
{
  "sources": ["36kr", "juejin"]
}
```

#### 2. 大模型 (LLM) 节点 Prompt 示例

**系统提示词 (System Prompt)**：
```markdown
你是一位专业的高级科技与商业资讯分析师。你的任务是将传入的实时热榜资讯整理成一份结构清晰、重点突出的《每日科技早报》。

请遵循以下输出规则：
1. 资讯筛选：过滤掉琐碎或重复内容，聚焦人工智能、前沿技术、互联网大厂动态与重要投融资。
2. 分类归纳：将资讯分为【科技焦点】与【开发者前沿】两个版块。
3. 格式规范：
   - 每条资讯提炼为一句话核心看点（不超过 50 字）。
   - 标注资讯来源（如 [36氪]、[掘金]）。
4. 语言风格：专业、精炼、客观，适合清晨快速阅读。
```

**用户提示词 (User Prompt)**：
```markdown
今日抓取到的热榜数据如下：
{{dailyHot.hotNewsList}}

请根据上述数据生成今日份的《每日科技早报》。
```

### 示例二：全网大众舆情与社会热点速览

#### 1. 工具节点输入配置

```json
{
  "sources": ["weibo", "zhihu", "toutiao"]
}
```

#### 2. 大模型 (LLM) 节点 Prompt 示例

**系统提示词 (System Prompt)**：
```markdown
你是一位敏锐的新闻媒体人与舆情分析专家。请根据传入的社交媒体与资讯热榜，总结当前全网最关注的 5 大热门议题。

输出要求：
1. 【议题概括】：用简洁有力的标题概括核心事件。
2. 【讨论阵地】：标明该议题在微博、知乎或头条中的讨论侧重点。例如：微博侧重事件突发与公众情绪，知乎侧重专业解读与利弊分析。
3. 【公众关注点】：总结网民关注的核心分歧或诉求（2~3 句话）。
```

## 注意事项

1. **网络连通性**：
   - 插件运行环境需要能够正常访问各平台的公开 API 接口域名（`gateway.36kr.com`、`api.zhihu.com`、`m.weibo.cn`、`api.juejin.cn`、`www.toutiao.com`）。
   - 若在内网或受限网络环境部署，请确保出站网络策略放行上述域名。
2. **字段差异与兼容性**：
   - 并非所有平台都返回 `time`（发布时间）和 `description`（内容摘要）。
   - 目前仅 **36氪** 和 **知乎** 接口返回发布时间，仅 **知乎** 返回内容摘要。在工作流设计中引用相关字段时应考虑可选情况。
3. **调用频率与稳定性**：
   - 本插件调用各平台开放接口，建议配合定时任务（如每小时或每日早晚一次）使用，避免短时间内高频次瞬时并发调用触发上游平台的防刷风控策略。
