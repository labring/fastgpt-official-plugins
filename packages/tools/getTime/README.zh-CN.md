# 获取当前时间 (getTime)

获取 FastGPT 运行时所处的当前系统时间，并将格式化的时间字符串提供给工作流下游节点使用。

## 工具简介

`getTime` 是 FastGPT 官方提供的核心系统工具之一。该工具直接读取 FastGPT 工作流执行上下文中的系统内置时间变量，无需依赖任何第三方外部 API 服务即可获取可靠的时间信息。在自动化工作流与 AI 智能体编排中，该工具常作为前置或辅助节点，为模型和逻辑控制提供即时的时间基准。

### 典型应用场景

- **提示词动态注入（Dynamic Prompt Injection）**：在调用大模型（LLM）前获取最新时间并注入到系统提示词（System Prompt）中，消除大模型因知识库截止时间导致的“时间幻觉”，使其能准确理解并回答“今天是周几”、“当前年份”、“距离某个时间节点还有几天”等强时间依赖的问题。
- **工作流时间校验与条件分支（Workflow Validation & Branching）**：在业务逻辑中用于判断用户咨询或任务触发是否在服务时间段（例如工作日 9:00 - 18:00）、判断限时活动/优惠券是否过期，配合条件分支节点进行精准路由。
- **外部接口请求参数构造**：调用需要时间戳签名（Timestamp）、日期过滤参数的第三方系统接口（如 CRM、ERP 或消息推送平台）时，作为时间戳生成器使用。

## 输入参数

该工具无需任何输入参数配置，也无需配置外部密钥（Secrets），节点触发时将自动从运行上下文中提取时间。

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 无 | - | - | - | 无需传入任何输入参数 |

## 输出结果

工具执行完成后，返回包含当前时间字符串的对象结构：

| 字段名 | 类型 | 描述 | 示例值 |
| :--- | :--- | :--- | :--- |
| `time` | string | 当前系统时间字符串 | `2025-05-20 13:14:00` |

### 输出示例

```json
{
  "time": "2025-05-20 13:14:00"
}
```

## 时区处理说明

1. **时间来源**：本工具直接获取 FastGPT 运行时系统变量 `systemVar.time`。
2. **时区基准**：时间字符串的具体时区与格式取决于 FastGPT 服务端部署环境的系统时区设置（如 Docker 容器中的 `TZ` 环境变量配置，常见的有时区为 `Asia/Shanghai` 对应的 UTC+8，或未显式配置时的 `UTC` 时间）。
3. **时区转换与格式化建议**：
   - 若业务需要跨国际时区显示（如 UTC、EST、PST 等），或需要特定格式（如仅获取年份/月份、Unix 时间戳毫秒数等），推荐将 `time` 输出连接至下游的 **代码运行节点（JavaScript/Python）**，通过内置的时间库（如 `dayjs` 或原生 `Date`）进行灵活的时区转换与解析处理。

## 在 FastGPT 工作流中的典型用法

### 示例 1：为 AI 对话动态注入当前时间（消除时间幻觉）

1. 在 FastGPT 应用画布中添加 **获取当前时间** 节点。
2. 将 **工作流开始** 节点的输出连接至 **获取当前时间** 节点。
3. 将 **获取当前时间** 的输出变量 `time` 连接至下游 **AI 对话** 节点的输入参数中。
4. 在 **AI 对话** 节点的系统提示词（System Prompt）中配置时间引用：
   ```markdown
   当前系统时间为：{{time}}。请根据该时间基准回答用户提出的与时间、日期相关的问题。
   ```

### 示例 2：工作流时间校验与业务分支流转

1. 在用户发起会话后，触发 **获取当前时间** 节点。
2. 将输出的 `time` 传入 **代码运行节点**，编写逻辑判断当前小时是否处于人工客服工作时间（例如 09:00 - 18:00）。
3. 根据代码节点返回的布尔值（如 `isWorkingHour`），使用 **条件分支（IF/ELSE）** 节点进行导流：
   - 若处于工作时间：路由至在线客服或工单转派节点；
   - 若非工作时间：自动触发提示回复并引导用户留言。
