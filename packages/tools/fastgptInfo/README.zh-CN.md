# FastGPT 宿主环境信息获取工具集 (FastGPT Information Retrieval)

`fastgptInfo` 是 FastGPT 官方提供的宿主环境与上下文信息获取工具集（System Toolset）。该插件无需配置任何外部 API 密钥，直接通过 FastGPT 内部运行上下文（Host Context）安全获取当前发起对话用户的账户名、成员名、联系方式、组织架构及所属群组。在智能体（AI Agent）编排与复杂工作流中，该工具常作为前置感知节点，为系统提供多租户识别、权限校验、条件分支路由及个性化服务能力。

## 典型应用场景

- **智能体个性化称呼与交互**：获取当前对话用户的账户名或成员昵称，在系统提示词（System Prompt）中动态注入用户名与称谓，打造富有温度、量身定制的专属交互体验。
- **多部门 / 组织条件路由**：根据用户所属的部门或组织架构路径（`orgs.pathId` / `orgs.name`），配合条件分支节点实现跨部门工作流分流，例如自动将销售部、研发部或财务部用户的提问导向各自专属的业务处理逻辑或专用工具。
- **会话用户身份识别与留痕**：在问答记录、工单提交、通知推送或外部系统（如 CRM、ERP）联动流程中，自动获取并附带用户的账号名（`username`）、成员名（`memberName`）与联系方式（`contact`），实现精确的会话身份追溯与审计留痕。
- **基于租户 / 群组的知识库问答权限控制**：读取用户所属群组（`groups.name`）或团队组织，动态匹配企业权限策略，控制特定敏感知识库、高级模型或高权限系统工具的调用权限，保障多租户场景下的数据安全。

## 前置依赖与系统要求

- **FastGPT 版本要求**：**FastGPT >= v4.14.7**。本插件依赖 FastGPT 宿主环境提供的 `ctx.invoke.userInfo` 上下文调用接口及 `userInfo:read` 系统权限声明。若在低于该版本的 FastGPT 运行，将因宿主缺少相应接口支持而导致调用失败。
- **密钥配置**：**无需配置任何外部 API 密钥（Secrets）**。插件属于 FastGPT 系统级上下文感知工具，执行时由宿主引擎自动从当前会话上下文中注入数据，免去任何第三方服务申请与鉴权配置流程。

## 子工具：获取用户信息 (`getUserInfo`)

### 1. 输入参数列表

本工具直接从 FastGPT 当前会话执行上下文中提取当前用户信息，**无需传入任何输入参数**。

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 无 | - | - | - | 无需传入任何输入参数 |

### 2. 输出结果说明

工具执行完成后，返回包含当前用户多维度身份信息的对象：

| 字段名 | 类型 | 可空 | 说明 |
| :--- | :--- | :--- | :--- |
| `username` | 字符串 (String) | 否 | 当前账户名（如系统注册用户名、手机号或账号标识符）。 |
| `memberName` | 字符串 (String) | 是 | 当前成员显示名称（在团队/组织内显示的成员姓名或昵称，若未单独设置可能为 `null`）。 |
| `contact` | 字符串 (String) | 是 | 当前用户的联系方式（如绑定的手机号码或电子邮箱，未设置时为 `null`）。 |
| `orgs` | 对象数组 (Array\<Object\>) | 否 | 当前账户所属的组织架构列表（支持多级或多个组织）。 |
| `orgs[].pathId` | 字符串 (String) | 否 | 组织的全局唯一路径标识（Path Identifier，例如 `root/tech-dept/frontend`）。 |
| `orgs[].name` | 字符串 (String) | 否 | 组织/部门的显示名称（例如 `前端研发组`）。 |
| `groups` | 对象数组 (Array\<Object\>) | 否 | 当前账户所属的团队群组/角色组列表。 |
| `groups[].name` | 字符串 (String) | 否 | 群组名称（例如 `技术研发团队`、`知识库协作者`）。 |

#### JSON 输出示例

```json
{
  "username": "zhangsan",
  "memberName": "张三",
  "contact": "13800138000",
  "orgs": [
    {
      "pathId": "root/tech-dept/frontend",
      "name": "前端研发组"
    }
  ],
  "groups": [
    {
      "name": "技术研发团队"
    },
    {
      "name": "知识库协作者"
    }
  ]
}
```

### 3. 典型工作流编排示例

#### 示例一：提示词动态注入用户信息（实现个性化交互）

1. 在 FastGPT 应用画布中添加 **获取用户信息 (`getUserInfo`)** 节点。
2. 将 **流程开始** 节点的输出连接至 **获取用户信息** 节点。
3. 将 **获取用户信息** 节点的输出变量连接至下游 **AI 对话** 节点。
4. 在 **AI 对话** 节点的系统提示词（System Prompt）中引用用户信息：
   ```markdown
   你是一位专业的企业智能协同助手。
   当前与你对话的用户信息如下：
   - 姓名：{{memberName}}（账号：{{username}}）
   - 联系方式：{{contact}}
   - 所属部门：{{orgs}}
   - 所属群组：{{groups}}

   请根据以上信息在回复时进行个性化称呼（优先称呼“{{memberName}}”），并结合其所在部门的业务背景提供针对性的解答。
   ```

#### 示例二：配合条件分支节点实现组织架构路由与权限控制

1. 用户发起对话后，前置触发 **获取用户信息 (`getUserInfo`)** 节点。
2. 将输出连接至 **条件分支** 节点（或代码运行节点进行数组匹配）。
3. 在条件分支节点中针对 `orgs` 或 `groups` 配置分流逻辑：
   - **分支 A（财务部分支）**：判断 `orgs` 中包含 `name == "财务部"`，流程路由至包含敏感财务报表知识库与财务审批工具的应用分支。
   - **分支 B（研发部分支）**：判断 `orgs` 中包含 `name == "研发部"`，流程路由至包含内部技术 API 文档与工单提报工具的分支。
   - **默认分支**：路由至面向全员的通用问答与企业制度知识库。
4. 有效防止普通员工越权访问敏感知识库或业务工具，实现零代码企业级细粒度权限管控。

### 4. 注意事项

1. **未登录访客与公开分享链接说明**：
   - 当应用通过**公开免密分享链接**、**未携带认证 Token 的外部 iframe 嵌入页面**或在**访客未登录状态**下访问时，会话上下文不存在真实的登录用户凭据。
   - 在此场景下，`username` 可能返回访客临时标识或匿名空值，`memberName` 与 `contact` 为 `null`，`orgs` 与 `groups` 将返回空数组 `[]`。
   - **最佳实践**：在下游工作流节点（如条件分支或代码运行节点）中引用上述字段时，建议添加防御性判空逻辑（如使用默认称谓“访客朋友”），避免因访问空值字段导致下游逻辑异常。
2. **FastGPT 版本依赖**：
   - 宿主系统必须运行 **FastGPT v4.14.7 或更高版本**。若在低于此版本的 FastGPT 环境中导入或运行本插件，工作流执行至该节点时将因宿主不支持 `ctx.invoke.userInfo` 而抛出执行异常。
3. **数据安全性与权限范围**：
   - 本插件在清单（manifest）中声明了 `userInfo:read` 权限，仅读取当前对话发起者自身的会话上下文基本信息，不跨越租户或访问其他用户的隐私数据，严格遵循企业数据隔离与安全规范。
