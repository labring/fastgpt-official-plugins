# Whisper 语音转文字 (Whisper Speech-to-Text)

FastGPT 官方 OpenAI Whisper 语音识别插件。利用 OpenAI Whisper 及最新转写大模型，快速将音频文件转换为高精度文本，支持多语种识别、自动标点与口语化转写，适配多种音频格式与灵活输入方式。

---

## 插件简介与典型应用场景

OpenAI Whisper 具备强大的多语言语音识别能力，经过海量弱监督音频数据训练，能够准确应对复杂的背景噪音、口音、专有名词和多语种混合对话场景。本插件不仅支持经典的 `whisper-1` 模型，还支持基于 GPT-4o 架构的最新语音转写模型，为 FastGPT 智能体提供可靠的听觉输入能力。

### 典型应用场景
- **语音留言与客服录音转写**：在在线客服、工单管理或呼叫中心场景下，将用户发送的语音条或通话录音即时转写为文字，便于下游大模型进行意图理解、情绪识别与工单自动派发。
- **会议纪要与访谈录音整理**：将企业内部会议、研讨会、媒体访谈或用户调研的长音频转换为文本稿，结合 FastGPT 大语言模型节点快速提取关键结论、讨论要点与行动待办（TODO）。
- **多模态语音交互输入**：在智能体工作流中充当“耳朵”，让用户直接以语音形式与 AI 助手沟通交流，实现自然的语音问答与交互式操作。
- **视频配音文本提取与字幕制作**：转写短视频、教学课件、播客音频的正文内容，快速生成文字底稿，用于字幕制作、内容合规审查或知识沉淀。

## 输入参数说明

在 FastGPT 工作流或智能体工具调用（Tool Call）中，支持以下输入参数：

| 参数名 | 对应字段 | 类型 | 是否必填 | 工具参数 (`isToolParam`) | 说明与示例 |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **转写模型** | `model` | 枚举字符串 | **是** | 是 (`true`) | 用于语音转写的模型名称，支持以下选项：<br>• `whisper-1`：OpenAI 官方通用语音识别模型，稳定成熟、性价比高，支持多语种转写。<br>• `gpt-4o-transcribe`：基于 GPT-4o 系列的高精度语音识别模型，具备更强的上下文理解与专有名词识别能力。<br>• `gpt-4o-mini-transcribe`：轻量版转写模型，延迟更低、成本更优，适合实时性要求高的转写场景。<br>• `gpt-4o-transcribe-diarize`：支持说话人分离（Diarization）的模型版本，适合多人会议与对话访谈。 |
| **音频文件** | `file` | 字符串 | **是** | 是 (`true`) | 待转写的音频文件，支持以下两种输入方式：<br>1. **公网可访问的下载直链 (URL)**：必须包含 `http://` 或 `https://`，例如 `https://example.com/audio.mp3` 或 FastGPT 宿主文件上传直链。<br>2. **Base64 Data URL 或纯 Base64**：例如 `data:audio/mp3;base64,SUQzBA...` 或原始 Base64 编码字符串。 |

## 典型工作流编排示例

在 FastGPT 中，将 Whisper 插件与大语言模型（LLM）节点组合，可以轻松搭建“语音输入 -> 文本提取 -> 智能处理”的全流程工作流：

### 1. 节点编排流程

```
[音频输入 / 上传文件]
         │
         ▼
[Whisper 语音转文字 (whisper)]
  ├── model: whisper-1
  └── file:  {{音频文件直链或 Base64}}
         │
         ▼ (输出 text 文本)
[大模型节点 (LLM / 意图识别或会议纪要)]
         │
         ▼
[文本输出 / 最终回复节点]
```

### 2. 编排步骤指南

1. **音频接收节点**：通过“用户问题”输入框（用户发送语音附件或文件链接），或上游自定义 Webhook 接收录音直链。
2. **Whisper 语音转文字节点**：
   - 将 `file` 参数绑定为上游音频直链或 Base64 变量。
   - `model` 建议首选 `whisper-1`（常规场景）或 `gpt-4o-transcribe`（专业名词较多场景）。
3. **大模型处理节点（以会议纪要为例）**：
   - 引用 Whisper 节点的输出变量：`{{text}}`。
   - 配置系统提示词（System Prompt）：
     ```markdown
     你是一位专业的高效会议秘书。请对以下由语音转写得到的文本进行整理和提炼：

     【语音转写原文】：
     {{text}}

     【任务要求】：
     1. 修正口语转写中的错别字与语病，保持语义连贯。
     2. 提取会议核心议题与决议事项。
     3. 整理明确的待办事项（Action Items），标明责任人与时间节点（若原文提及）。
     4. 输出格式清晰优雅，采用 Markdown 列表呈现。
     ```
4. **输出回复节点**：将整理后的结构化会议纪要直接展示给用户或保存至知识库。

## 注意事项与最佳实践

1. **支持的音频格式**
   - 兼容 OpenAI Whisper 官方支持的主流音频封装格式，包括：`mp3`、`mp4`、`mpeg`、`mpga`、`m4a`、`wav`、`webm`。
   - 若使用 Base64 Data URL 形式传入，前缀建议明确声明正确的 MIME 类型（如 `data:audio/mp3;base64,...` 或 `data:audio/wav;base64,...`）。

2. **音频文件大小限制**
   - OpenAI 官方对单次请求上传的音频文件有 **25 MB** 的上限限制。
   - 对于超过 25 MB 的长音频，建议在上游预先进行压缩（如转为 64kbps 的 MP3/M4A 格式）或切分为分段音频后再分批调用。

3. **网络连通性与链接有效性**
   - 当以 URL 直链形式传入 `file` 时，必须保证 FastGPT 宿主环境能够直接访问该公网地址。
   - 避免使用需要登录 Cookie、防盗链签名过期或内网局域网（无法穿透）的音频直链。

4. **中继网关与网络超时设置**
   - 音频文件在传输和转写阶段需要一定时间（例如一段 10 分钟的录音通常需要 10~25 秒转写时间）。
   - 若使用了反向代理（如 Nginx）或自建 API 中转网关，请务必将 `proxy_read_timeout` 或接口超时时间调整为 **60 秒或以上**，防止因网关超时断开连接导致 504 错误。

5. **传输方式选型建议**
   - **大文件优先推荐 URL 直链**：Base64 编码会带来约 33% 的额外数据体积膨胀并占用更多内存，对于大于 5MB 的音频文件，建议优先通过对象存储直链或宿主直链传递。
